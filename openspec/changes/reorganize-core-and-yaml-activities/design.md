# Design

## Context

See `proposal.md` for motivation and scope. Today the core library and Ringer workflows have accumulated structural drift across four areas:

1. **Quantization fragmentation**: `quantization/quantizers.py` (`FixedPointQuantizer` with `integer_bits`/`fractional_bits`), `quantization/keras.py` (`FixedPointQuantizationDense` with `integer_bits`/`floating_bits`), and `quantization/hgq.py` (`HGQFixedPointConfig` with constant-only `i0`/`f0`) do not share a common interface or union. `RingerKerasTrainingJob` only wires `MLPFactory | FixedPointQuantizedMLP`, leaving `HGQ2FixedPointQuantizedMLP` unreachable from YAML training jobs, and `HGQFixedPointConfig` cannot express learnable bitwidth ranges (`MinMax`) for bit optimization.
2. **Split layer/model factories**: Dense factories live in `models/dense.py`, KAN factories in `models/kan.py`, quantum layers in both `layers/quantum.py` and the older `models/quantum.py`, and `KerasSequentialModelFactory` in `models/keras/factories.py` (which omits quantized dense layers).
3. **Duplicate committee implementations**: `models/binned_committee.py` (`BinnedModel`/`BinnedCommittee` with `backend="hgq"|"custom"`) and `workflows/ringer/models.py` (`BinnedSpecialistModel`/`BinnedSpecialistCommittee` used by all CLI workflows) duplicate bin-routed inference and PTQ logic.
4. **Ad-hoc workflow boilerplate**: The four YAML activities in `workflows/ringer/` each repeat `YamlBaseModel`, `output_path` serialization, `config.json` dumping, logger setup, and Typer CLI command wiring.

Constraints from the repository:
- Python 3.12+, Pydantic v2 (`extra="forbid"`, `frozen=True`), Polars lazy/streaming data handling, Keras 3 (`KERAS_BACKEND=tensorflow` by default; `KERAS_BACKEND=torch` required for `TorchModuleWrapper`-based KAN and PennyLane quantum layers).
- `hgq2==0.2.0` exposes `hgq.constraints.Constant(value)` and `hgq.constraints.MinMax(min_value, max_value)` for `ic`/`fc` on `QuantizerConfig(q_type="kif", ...)`.
- Standalone operating-point JSON files generated by `threshold-fit` must remain self-contained and reloadable.
- `notebooks/`, `src/neuralnet/torch/`, and `src/neuralnet/tensorflow/` remain untouched in this change.

## Goals / Non-Goals

**Goals:**
- Provide an extensible `QuantizerConfig` discriminated union (`object_type`) with unified `integer_bits`/`fractional_bits` nomenclature across custom fixed-point & Polars normalizers (no retrocompatible `floating_bits` alias) and native `hgq2` field names (`k0`, `i0`, `f0`, `ic`, `fc` with `Constant`/`MinMax` constraints) for HGQ2 bitwidth optimization.
- Consolidate all Keras 3 layer factories into `src/neuralnet/layers/` with an explicit factory per layer type (`DenseFactory` strictly floating-point, `FixedPointQuantizedDenseFactory` with its own custom fixed-point logic, `HGQ2DenseFactory` with its own HGQ2 range-aware logic, `KAN1DLayerFactory`, and PennyLane quantum factories) and expose a unified `KerasSequentialModelFactory` plus specialized `MLPFactory` and `KANFactory` in `src/neuralnet/models/`.
- Consolidate specialist committee logic into a single canonical implementation (`src/neuralnet/models/committee.py`).
- Introduce `BaseActivity(YamlBaseModel)` and a uniform Typer CLI registration helper for the existing 4 Ringer activities (`training`, `threshold-fit`, `inference`, `alternative-norm1`).
- Migrate all existing repository YAML files (`tests/data/*.yaml`, `jobs/**/*.yaml`) to the unified schema.
- Retire duplicate `models/quantum.py` and deprecate `models/vkan.py`.

**Non-Goals:**
- Preserving retrocompatible YAML aliases (`floating_bits`, `fixed_point_quantized_mlp`, `hgq2_mlp`).
- Converting `notebooks/` into YAML activities (deferred to future changes).
- Adding new CLI activities such as standalone `ptq`, `compare`, or `exploratory` workflows.
- Modifying or removing `src/neuralnet/torch/` or `src/neuralnet/tensorflow/`.
- Implementing new quantization algorithms beyond unifying custom fixed-point and HGQ2 (this change builds the extension point for them).

## Decisions

### Decision 1: Discriminated-union quantization configs with native range-aware HGQ2 (`neuralnet.quantization`)
- **Choice**: Define `KerasQuantizerProtocol` (and `PolarsQuantizerProtocol`) in `src/neuralnet/quantization/base.py`, with concrete Pydantic config classes discriminated by `object_type`:
  - `CustomFixedPointQuantizer` (`object_type: Literal["custom_fixed_point"]`) using `integer_bits: int` (`> 0`) and `fractional_bits: int` (`> 0`), unifying `FixedPointQuantizer` (Polars) + `FixedPointQuantizationDense` + `fixed_point_quantize` (Keras).
  - `HGQ2QuantizerConfig` (`object_type: Literal["hgq2_fixed_point"]`) preserving native `hgq2` parameter names: `k0: bool = True`, `i0: int`, `f0: int`, plus optional `ic` and `fc` constraint configs (supporting `Constant` — defaulting to `Constant(i0)` / `Constant(f0)` — or `MinMax(min_value, max_value)` validated against `max_value >= min_value` and `min_value <= i0/f0 <= max_value`), allowing `QDense` to optimize bitwidths during training while matching `hgq2` documentation directly.
  - Export `type QuantizerConfig = Annotated[CustomFixedPointQuantizer | HGQ2QuantizerConfig, Field(discriminator="object_type")]` and a helper `get_custom_objects()` aggregating Keras custom objects across all registered strategies.
- **Why**: Keeps custom fixed-point nomenclature consistent across `neuralnet` (`integer_bits`/`fractional_bits`) while keeping HGQ2 configs 1:1 with the `hgq2` framework's own terminology (`k0`, `i0`, `f0`, `ic`, `fc`), and lets future non-HGQ2 quantization techniques drop in their own `object_type` config and layer factory.
- **Alternatives considered**:
  - *Renaming HGQ2 fields to `integer_bits`/`fractional_bits`*: Rejected so users configuring `hgq2` can use the exact parameter names from `hgq2` docs (`k0`, `i0`, `f0`, `ic`, `fc`).

### Decision 2: Explicit per-layer factories in `neuralnet.layers` (no quantizer on `DenseFactory`)
- **Choice**: Keep every layer type explicit in `src/neuralnet/layers/` with **no quantizer field on `DenseFactory`** — each quantized dense layer owns its own dedicated quantizer logic:
  - `layers/dense.py`:
    - `DenseFactory` (`object_type: Literal["dense"]`) — strictly floating-point `keras.layers.Dense` only.
    - `FixedPointQuantizedDenseFactory` (`object_type: Literal["fixed_point_quantized_dense"]`) — uses its own custom fixed-point quantizer logic (`CustomFixedPointQuantizer` with `integer_bits`, `fractional_bits`) and builds `FixedPointQuantizationDense`.
    - `HGQ2DenseFactory` (`object_type: Literal["hgq2_dense"]`) — uses its own HGQ2 quantizer logic (`HGQ2QuantizerConfig` with native `k0`, `i0`, `f0`, `ic`, `fc` supporting `Constant` and `MinMax` bit optimization) and builds `hgq.layers.QDense`.
    - Exports `type DenseLayerType = Annotated[DenseFactory | FixedPointQuantizedDenseFactory | HGQ2DenseFactory, Field(discriminator="object_type")]`.
  - `layers/kan.py`: `KAN1DLayerFactory` (moved from `models/kan.py`), with backend validation checking `keras.config.backend() == "torch"`.
  - `layers/quantum.py`: Canonical PennyLane quantum layer factories (already here; add consistent backend check for `torch`), retiring `models/quantum.py`.
  - `layers/__init__.py`: Exports `type LayerType = Annotated[DenseFactory | FixedPointQuantizedDenseFactory | HGQ2DenseFactory | KAN1DLayerFactory | BasicEntanglerQuantumLayerWithAnglerEmbeddingFactory | StronglyEntanglingQuantumLayerWithAnglerEmbeddingFactory | HardwareEfficientQuantumLayerWithAnglerEmbeddingFactory, Field(discriminator="object_type")]`.
- **Why**: Explicit factories make YAML configs immediately readable (`object_type: hgq2_dense` vs `object_type: fixed_point_quantized_dense` vs `object_type: dense`), keep `DenseFactory` strictly floating-point (`extra="forbid"`), and let each quantization backend own its own quantizer config and layer-construction logic cleanly.
- **Alternatives considered**:
  - *Pluggable `quantizer` field on `DenseFactory`*: Rejected — `DenseFactory` stays pure floating-point, while HGQ2 and custom quantized dense layers each have their own explicit factory and dedicated quantizer logic.

### Decision 3: `KerasSequentialModelFactory` + specialized convenience factories (`MLPFactory`, `KANFactory`)
- **Choice**: Organize `src/neuralnet/models/` around:
  - `models/sequential.py`: `KerasSequentialModelFactory` (`object_type: "keras_sequential"`) taking `layers: list[LayerType]` (min length 1).
  - `models/mlp.py`: `MLPFactory` (`object_type: "mlp"`) taking `layers: list[DenseLayerType]` (so one `MLPFactory` supports FP, custom fixed-point, HGQ2, or mixed dense-family MLPs with explicit per-layer `object_type`).
  - `models/kan.py`: `KANFactory` (`object_type: "kan"`) taking `model_shape: list[int]`, `grid_size`, `spline_order`, building a `keras.Sequential` of `KAN1DLayerFactory` layers.
  - `models/__init__.py`: Exports `type ModelFactoryType = Annotated[KerasSequentialModelFactory | MLPFactory | KANFactory, Field(discriminator="object_type")]`.
  - Wire `ModelFactoryType` directly into `RingerKerasTrainingJob.model_factory`.
- **Why**: Gives users full expressiveness with `keras_sequential` for hybrid models (e.g., Dense + Quantum, or HGQ2 Dense + KAN) while keeping common homogeneous models concise via `mlp` and `kan`.

### Decision 4: Single `BinnedSpecialistCommittee` implementation
- **Choice**: Consolidate `models/binned_committee.py` and `workflows/ringer/models.py` into `src/neuralnet/models/committee.py` (`BinnedSpecialistModel` and `BinnedSpecialistCommittee`), using `Transformation` protocol (fixing the `Tranformation` typo) and accepting `QuantizerConfig` in `quantize(...)` / `fixed_point_quantization(...)`. Use `get_custom_objects()` when loading `.keras` files so custom and HGQ2 models deserialize seamlessly.
- **Why**: Eliminates two diverging committee implementations where one had HGQ2 support and the other powered all workflows.

### Decision 5: Shared `BaseActivity(YamlBaseModel)` and CLI registration helper
- **Choice**: Create `src/neuralnet/workflows/base.py` defining:
  - `BaseActivity(YamlBaseModel, ABC)` with `model_config = ConfigDict(extra="forbid", frozen=True)`, standard `output_path` (`PlainSerializer(str)`), `logger_name`, `dump_config()` (writes `output_path/config.json`), and abstract `submit()`.
  - `register_activity_command(app, name, activity_cls, short_help, description)` helper to eliminate the repeated Typer command boilerplate in `workflows/ringer/cli.py`.
- **Why**: All four existing activities (`training`, `threshold-fit`, `inference`, `alternative-norm1`) immediately follow one reproducible contract, and future notebook-to-YAML activities can be added in a few lines.

## Risks / Trade-offs

- **[Breaking YAML schema changes — no retrocompatibility]** → Unifying custom fixed-point bitwidth nomenclature to `integer_bits`/`fractional_bits` (dropping `floating_bits` with no compatibility aliases, while keeping native `hgq2` field names `k0`, `i0`, `f0`, `ic`, `fc` on HGQ2 configs) and replacing `FixedPointQuantizedMLP` / `HGQ2FixedPointQuantizedMLP` with `MLPFactory` + explicit layer factories (`fixed_point_quantized_dense`, `hgq2_dense`) is an intentional clean break. Mitigation: Update all existing YAML files in the repository (`tests/data/*.yaml`, `jobs/**/*.yaml`) to the new schema as part of this change.
- **[Keras 3 backend mismatch at runtime]** → `KAN1DLayerFactory` and Quantum layers require `KERAS_BACKEND=torch`, whereas `RingerKerasTrainingJob` defaults to `tensorflow`. Mitigation: Validate `keras.config.backend()` inside `as_keras()` with an explicit, actionable `ValueError`, and test both backends in `pytest`.
- **[HGQ2 model serialization/deserialization]** → Reloading `QDense` layers via `keras.saving.load_model` requires HGQ2 layers to be imported/registered. Mitigation: Centralize custom-object discovery in `quantization.base.get_custom_objects()` and ensure `hgq.layers` is lazily imported when `hgq2` is installed.
- **[Import path churn]** → Moving layer factories into `neuralnet.layers` and consolidating `BinnedSpecialistCommittee` changes internal module paths. Mitigation: Keep clean top-level re-exports in `neuralnet.layers`, `neuralnet.models`, and `neuralnet.quantization`, and remove obsolete duplicates (`models/binned_committee.py`, `models/quantum.py`) cleanly with all internal imports and tests updated.

## Migration Plan

1. Implement `neuralnet.quantization` base protocol + unified `CustomFixedPointQuantizer` and range-aware `HGQ2QuantizerConfig` (no legacy field aliases), and update `normalizers/factories.py` to compose `FixedPointQuantizer`.
2. Build `neuralnet.layers` (`dense.py` with explicit `DenseFactory`, `FixedPointQuantizedDenseFactory`, `HGQ2DenseFactory`; `kan.py`; `quantum.py`; `__init__.py`) and retire `models/quantum.py`.
3. Build `neuralnet.models` (`sequential.py`, `mlp.py`, `kan.py`, `committee.py`, `__init__.py`), remove `models/binned_committee.py` and `models/dense.py`, and deprecate `models/vkan.py`.
4. Add `workflows/base.py` (`BaseActivity` + CLI registration helper), migrate the 4 Ringer activities (`training`, `threshold-fit`, `inference`, `alternative-norm1`) and `workflows/ringer/cli.py`, and update all existing repository YAMLs (`tests/data/*.yaml`, `jobs/**/*.yaml`) to the new schema.
5. Update unit and integration tests across `tests/` and verify with `uv run pytest` and `uv run ruff check .`.
